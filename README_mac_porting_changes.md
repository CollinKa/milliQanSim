# MilliQanSim macOS Porting Notes

This note summarizes the local changes that matter for the current macOS Apple
Silicon setup. The working configuration is Geant4 10.7.4 with Qt support, not
the earlier Geant4 11.x attempt.

## Current working target

The local visual workflow uses the `Bench` executable and the slab benchmark
setup:

```bash
source /opt/miniconda3/etc/profile.d/conda.sh
conda activate milliqan-sim
source /Users/haoliangzheng/software/geant4-10.7.4-qt-install/bin/geant4.sh
export Geant4_DIR=/Users/haoliangzheng/software/geant4-10.7.4-qt-install/lib/Geant4-10.7.4

cd /Users/haoliangzheng/Desktop/CERN/milliQanSim
bash benchSetupSlab.sh
```

Then launch:

```bash
cd /Users/haoliangzheng/Desktop/CERN/milliQanSim/build
./Bench
```

and execute:

```text
/control/macroPath /Users/haoliangzheng/Desktop/CERN/milliQanSim/runMac
/control/execute visQt.mac
```

## Source and build changes

### `Bench.cc`

`Bench` now uses a Qt UI session in interactive and GUI modes:

```cpp
G4UIExecutive * session = new G4UIExecutive(argc, argv, "qt");
```

This is required for `OGLSQt`. If `Bench` uses `G4UIterminal`, Geant4 can list
`OGLSQt` as a candidate but still reject `/vis/open OGLSQt ...` as incompatible
with the current session.

### `runMac/visQt.mac`

This macro opens the Qt OpenGL viewer:

```text
/vis/open OGLSQt 1600x1200
```

It also draws the detector, sets a useful view, enables trajectory drawing by
particle ID, and accumulates events.

### `CMakeLists.txt.Bench`

The Bench CMake file was updated for the local conda/macOS environment:

- `cmake_minimum_required(VERSION 3.16 FATAL_ERROR)`
- Boost include path uses `$CONDA_PREFIX/include` when conda is active.
- The generated ROOT dictionary is `BenchDict`.
- `BenchCore` links against ROOT libraries directly.

These changes avoid Linux-only hard-coded paths and missing ROOT symbols in the
shared library.

### `CMakeLists.txt`

`benchSetupSlab.sh` copies `CMakeLists.txt.Bench` to `CMakeLists.txt`. Therefore
changes in the active `CMakeLists.txt` may be generated by the setup script. Edit
`CMakeLists.txt.Bench` for persistent Bench changes.

### `buildsetup.sh`

The config copy command was made portable on macOS:

```bash
cp -r inputData/config build
```

### `src/Bench/mqDetectorConstruction.cc.slab`

The optical data readers were bounded so they do not write past the fixed-size
arrays:

```cpp
while (ScintEntry < nEntries && ReadEJ200 >> pWavelength >> pSEff) {
    ...
}
```

and:

```cpp
while (PMTEntry < nEntriesPMT && ReadPMTQEff >> pWavelength >> pQEff) {
    ...
}
```

The active `src/mqDetectorConstruction.cc` is copied from this file by
`benchSetupSlab.sh`, so the persistent fix belongs in the Bench slab source.

## Generated or setup-script changes

Several files in the repo can appear modified after `benchSetupSlab.sh` because
the script copies files from `include/Bench`, `src/Bench`, and `defaultSlab`
into the active include and source paths. These are not all hand edits.

Examples include:

- `src/mqDetectorConstruction.cc`
- `src/mqPMTSD.cc`
- `src/mqScintSD.cc`
- `src/mqShieldingPhysicsList.cc`
- `src/mqTrackingAction.cc`
- matching headers under `include/`

Before committing, compare the generated active files with their source files
under `src/Bench` or `include/Bench`, and commit the source variant if the change
should survive the next setup-script run.

## External Geant4 package-cache patch

The Qt Geant4 install generated a package cache entry that newer CMake rejected:

```text
/Users/haoliangzheng/software/geant4-10.7.4-qt-install/lib/Geant4-10.7.4/Geant4PackageCache.cmake
```

The problematic `EXPAT_LIBRARY` entry was fixed locally to point to:

```text
/opt/miniconda3/envs/milliqan-sim/lib/libexpat.dylib
```

This patch is outside the repository, but it is required for clean CMake
configuration against the Qt Geant4 install on this machine.
